# 自建中继操作说明

发送端持有中继密钥才能开房间。接收方使用原版 croc v11，命令里只有中继地址和取件码，看不到密钥。文件内容仍由取件码加密，中继只转发密文。

不要再用官方安装命令部署这台中继：

```bash
curl -L https://getcroc.schollz.com | bash
```

官方 `croc relay` 要求发送和接收提交同一把密码。本文的 `croc-relay` 才按上面的规则准入。

## 密钥放在哪里

密钥只出现在两个地方：

- 服务器上 systemd 的启动参数
- 发送端 croc-desktop 的「设置 → 中继密码」

复制给别人的命令、聊天记录和二维码里都没有这把密钥。接收方电脑上不要设置 `CROC_PASS`。原版 croc 会读取这个环境变量；设成别的值时，接收会被拒绝。

知道中继地址和当次取件码的人，可以收走你正在等待的那一次文件。没有密钥的人不能用这台中继自行发送。

## 1. 编译中继

在本仓库根目录执行。服务器是 x86_64 时：

```powershell
$env:GOOS = "linux"
$env:GOARCH = "amd64"
$env:CGO_ENABLED = "0"
go build -trimpath -ldflags="-s -w" -o bin\croc-relay-linux-amd64 .\cmd\croc-relay
Remove-Item Env:GOOS, Env:GOARCH, Env:CGO_ENABLED
```

ARM 服务器把 `GOARCH` 改成 `arm64`。编译结果在 `bin\`，不进入 git。

## 2. 安装到服务器

把二进制和 `scripts/install-relay.sh` 拷到服务器，例如 `/root/croc-relay` 和 `/root/install-relay.sh`。在服务器上执行：

```bash
sed -i 's/\r$//' /root/install-relay.sh
RELAY_PASS='你的发送密钥' bash /root/install-relay.sh /root/croc-relay
```

脚本会：

1. 把程序装到 `/usr/local/bin/croc-relay`
2. 停掉并禁用旧的 `croc.service`，避免继续占用端口
3. 写入并启动 `croc-relay.service`
4. 在检测到 ufw 时放行 `9009:9013/tcp`

没有 ufw 时，自行放行这五个 TCP 端口。CentOS / RHEL：

```bash
firewall-cmd --permanent --add-port=9009-9013/tcp && firewall-cmd --reload
```

控制端口是 `9009`，`9010`–`9013` 是文件通道。云厂商安全组也要放行同样的端口。

更新程序时，重新编译、再次运行安装脚本即可。密钥保持不变。

## 3. 发送端设置

打开包含本次改动的 croc-desktop。本机编译产物是 `bin\croc-desktop.exe`；若旧窗口还在，先完全退出再打开新程序。

在「设置」中：

| 项 | 填写 |
| --- | --- |
| 中继地址（IPv4） | `服务器公网 IP:9009` |
| 中继密码 | 与服务器 `RELAY_PASS` 相同 |
| 中继地址（IPv6） | 留空。填了自定义 IPv4 后，IPv6 不会参与传输 |

保存后，「当前中继」只显示实际使用的 IPv4 地址。

本机如果开着 Clash 等代理，给这台中继的公网 IP 加直连规则，并重载配置。域名规则覆盖不到纯 IP。示例：

```yaml
IP-CIDR,你的中继IP/32,DIRECT,no-resolve
```

## 4. 发送与接收

1. 发送端选择文件，点发送。大文件会先显示「正在校验文件…」，校验结束后回到等待接收。
2. 点「复制命令」。Windows 上类似：

   ```text
   croc --relay 203.0.113.10:9009 dig-park-icon
   ```

   确认其中没有 `--pass`。
3. 把这条命令发给对方。对方安装原版 croc v11 后直接粘贴执行。
4. 传输开始后，进度下方会写「经中继转发」或「点对点直连」。
5. 对方尚未连接时可以取消，或按 Esc。取件码只在这次发送还连着中继时有效；取消或关闭后，同一条码不能再取走这次文件。

接收方也可以使用 croc-desktop：中继地址填同一台服务器，中继密码留空（程序会使用公开的默认密码），再输入取件码。

局域网探测超时不会再中断传输，程序会继续走中继。

## 5. 检查与故障

服务器上：

```bash
systemctl status croc-relay --no-pager
journalctl -u croc-relay -n 50 --no-pager
ss -lntp | grep -E '9009|9010|9011|9012|9013'
```

| 现象 | 处理 |
| --- | --- |
| 接收方提示 `bad password` | 对方环境里有 `CROC_PASS`，先取消该变量。或服务器仍在跑官方 `croc relay`，确认 `croc.service` 已停、`croc-relay.service` 在听 9009。 |
| 发送端提示 `bad password` | 桌面端中继密码与服务器 `RELAY_PASS` 不一致。 |
| 连接超时，本机地址是 `198.18.x.x` | 代理把中继流量拐走了。为中继 IP 添加上面的 `IP-CIDR` 直连规则。 |
| 对方先执行命令，提示进不了房间 | 发送端还没进入等待。先在桌面端点发送，再把命令给对方。 |
| 复制命令里出现 `--pass` | 还在用旧的桌面程序。完全退出后打开新编译的 `bin\croc-desktop.exe`。 |
